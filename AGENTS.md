# SceneSnap — agent notes

## Gate (run all before any push; every command must exit 0)

```bash
cp index.js /tmp/ss_gate.mjs && node --check /tmp/ss_gate.mjs   # ESM parse (node --check on .js parses CommonJS — always check a .mjs copy)
node test.mjs                                                    # behavior harness; exit 1 on any failure
npx -y eslint@9 index.js test.mjs                                # lint (config is import-free; no install needed)
```

Negative-test any NEW guard by reintroducing its bug in a scratch copy and proving the harness fails:

```bash
cp index.js /tmp/broken.js   # then delete the guard line in /tmp/broken.js
SS_SRC=/tmp/broken.js node test.mjs   # MUST exit 1
```

Version discipline: `manifest.json` version and the `const VERSION` stamp in `index.js` must match — the harness asserts it. Bump on every push; changelog entry in README with every change.

## Architecture (index.js, single file)

- **Builder transport ladder** (`callLLM`): Connection Manager profile → `ctx.generateRaw({prompt, systemPrompt})` → `generateQuietPrompt`. generateRaw is the preset-free path: a quiet prompt runs through the full generation pipeline, so a heavy RP preset (laws, CoT) contaminates builder output. Never reorder this ladder.
- **Grounding** (`collectSceneGrounding`): presence markers `[IST: name|state]` / `[ACW: name|...]` from the newest message that prints them (walk-back 6, same defaults as Summaryception; its user-configured patterns are respected when set), per-character `state` from `chatMetadata.summaryception.ledger`, and 500-char tails of the two preceding turns. All sources degrade to nothing without error — grounding is fuel, never a dependency. Pure cores (`scanPresenceIn`, `markerDetails`, `ledgerStateLines`) are separated from ctx wrappers for testability.
- **Dialogue bubbles**: builder returns `bubbles:[{speaker,text}]` per panel (JSON mode); `sanitizeBubbles` enforces the **verbatim guarantee** — a bubble renders only if its text literally occurs in the scene (normalized for curly quotes/case/whitespace). Verify FIRST, length-trim SECOND. Cap 2/panel, 90 chars. `overlayBubbles` draws them on canvas (backend-agnostic, pixel-legible); overlay failure ships the clean panel, never kills the image. Recovery paths (truncated JSON) drop bubbles rather than risk unverified text.
- **Backends**: runware (WS), novelai via ST route, novelai multi-char via direct API (zip extract), pollinations. Multi-char is single-frame; bubbles apply there via top-level `bubbles` key.
- **Anything the extension computes is stripped from every builder-writable field**: counts (`CODE_OWNED_TAG`) and clothing are code-owned. A count tag inside a character block is a second subject declaration to the image model and fuses the frame's characters — this is not cosmetic.
- **Anchor dedup must never delete a claim about a DIFFERENT subject**: `dress` describes what the world wears; a character block describing the same garment is a different claim. Bind population-scoped tags to the population (`crowd in <garment>`) so dedup cannot collapse them.
- **The seed's job is the place, not the people** (0.15.0, supersedes 0.12.5's rationale): identity is welded verbatim, so seed decorrelation is only the backstop for panels the weld does not cover. Welded panels share the run seed or the strip changes location between frames.
- **Count tags are a population claim, not a subject list**: `1boy, 1girl` tells the model the frame contains exactly two people. Never emit exhaustive counts for a frame whose anchor names a crowd — `framesCrowd()` reads the same words the model reads and `assembleIdentity` admits the crowd. A count that contradicts the frame is answered by the model deleting people.
- **`who` is principals only**: `splitPrincipals()` demotes any entry whose state places it distant/tiny/background before the weld, and never returns zero principals. A background figure in `who` costs a subject slot, a count, and a verbatim appearance block on someone three pixels tall.
- **An establishing frame is legal**: `"who": []` declared explicitly means the crowd or the place is the subject. Never conflate it with an OMITTED `who` (`whoDeclared`) — the corrective retry targets omission only. Conflating them makes a crowd-subject panel impossible to request, which is how a scene about three hundred people roaring came back as four close-ups.
- **NEVER ADD A TAG BECAUSE THE REASONING SAYS IT SHOULD HELP** (0.21.0, reverts 0.14.0/0.15.0): `crowd` was added from an argument about count contradictions and it produced the exact artifact it was meant to prevent, for seven versions. A tag's effect is an empirical fact about the image model, not a deduction. When the user has before/after images of the same scene, that A/B outranks any reasoning about what a tag "should" do.
- **Population belongs in the setting's own words, never in the count run.** `6+boys`/`6+girls` populate a frame; `crowd` alone describes a mood and leaves it empty.
- **Repeated attributes stack**: stature, age, and size stated in the cast block AND the state AND the sentence compound into caricature. Each attribute has exactly one owner — the cast sheet — and `scrubState` drops restatements.
- **Environment facts have ONE OWNER: the anchor** (0.22.0). The builder will restate the whole location block inside every panel prompt no matter how the law is worded — a rule the model must merely obey is not enforceable, so `dedupeAgainstAnchor()` deletes the restatement in code on both panel paths. The restatement is not bloat-only: it drowns the frame's action tags and stacks atmosphere until the crowd fogs out of existence.
- **A demotion must carry the demoted figure's verb** (0.22.0): `splitPrincipals()` demotes the person, never the action. A background figure reduced to a bare `distant figure` leaves its action-object unowned in the shared prompt, and the model binds it to the only principal left — the field run had a saluting old man holding the protagonist's sword. `backgroundFigureTag()` welds the action (scrubbed of appearance/garments) onto the demotion.
- **Every identity SOURCE needs its own guard, not every pipeline stage** (0.23.0): `scrubState` cleaned builder-written state, but the cast sheet is user/auto-built data welded verbatim — `shinigami uniform` there bypassed every garment law and produced the exact modern-military blend the laws were written to prevent. Guards belong at the point of welding, on every input path.
- **A negative prompt cannot beat an explicit positive.** Anti-modern negatives are the backstop; when a role-uniform is IN the positive (cast block), only removal works. Check positives before blaming negatives.
- **NAI route facts (0.24.0, from ST source + official docs)**: ST hardcodes `qualityToggle: false` + `use_order: true` → quality tags belong FIRST, in `{}`. Emphasis syntax (`{}`, `1.5::x::`, V4.5 negative `-1::x::`) survives the route inside `v4_prompt.caption.base_caption`. `characterPrompts: []` is hardcoded — char_captions are impossible via ST.
- **A principal who is only SEEN is not a principal** (0.25.0): `seen from behind/above/below` states demote exactly like `in the background`. And a strip has ONE sky: the anchor owns time-of-day; panel light tokens are code-dropped.
- **Every guard needs its exception's exception** (0.26.0): demotion is forbidden in explicit frames (`EXPLICIT_STATE`) — a from-behind PARTNER is the position, not scenery. And the weld must undress (`applyUndress`) when the state says clothing came off; a welded garment beats anatomy every time. Position is strength everywhere: welded garments go BEFORE state, crowd words hoist FORWARD of the anchor tail.
- **Caps amputate silently** (0.27.0): any char cap on a field that carries required detail is a content bug waiting for a long input. Explicit states get 420. And every enforcer that scrubs the shared prompt must also scrub STATE — the builder routes around enforcement through any field the enforcer doesn't read.
- **Field A/B > docs > reasoning** (0.28.0): the doc-backed quality block and the reasoning-backed `6+boys` headcount BOTH died to user A/Bs (worse aesthetics, egg-head crowds). Quality words are banned on NovelAI; population comes from the anchor's own words. And model choice is content policy: V4.5 Curated suppresses explicit anatomy — the extension warns on explicit+Curated.
- **Explicitness is PANEL-LEVEL data** (0.29.0): 'nude' in the environment contradicting welded garments renders clothed people — nudity is welded into every principal's state. A sex act with zero genital tags is a builder failure with a corrective retry. Role words ('soldiers', 'officers') summon modern armies no negative can stop — purge them when the gate fires.
- **Builders euphemize** (0.30.0): any NSFW detector must catch 'drives deep' and 'stays buried inside her', not just danbooru act names. And NAI craft (emphasis, order) belongs in the BUILDER's guidance (NAI_GUIDANCE), chosen per-panel — code braces on everything were A/B-rejected, builder braces on 1-3 critical tags are the docs' intent.
- **Never require the word the builder won't write** (0.31.0): nudity detection keyed on literal 'nude' failed three versions running — explicit panels are nude BY DEFAULT now, with clothes-stay-on as the opt-out. And world dress is a VOTE: a garment with exactly one cast-line owner is personal, never world dress.
- **The scene's tracker is the top clothing authority** (0.32.0): `| nothing |` in the header beats builder states AND cast sheets. Never encode beat TEMPLATES (the 0.31.0 arc law, reverted in a day) — beats are read from the scene's own action sequence. And the verbatim bubble matcher must fold em-dashes or cries die in verification.
- **THE COUNT RUN IS POSITIONAL**: tag models read counts in order against the blocks that follow. Counts must be emitted in BLOCK order, and nothing may sit between the count run and the first character block — an environment tag there (like `crowd`) both breaks the association and attracts that character's traits.
- **A structural requirement the model must JUSTIFY is enforceable; a rule it must merely obey is not.** `follows` and `between` work because an empty field is a code-detectable failure. When a semantic rule keeps being violated, give it a field.
- **NEVER TWO IDENTITY SOURCES FOR ONE CHARACTER** (0.19.0, reverses 0.17.0): a character name tag and a body description in the same block fight each other and blend. The body is the only source. `stripNameTags` removes a name tag and its single-word work-tag partner at the weld, so a sheet built under 0.17.0 needs no rebuild.
- **Never pipe a gate command through grep and echo a result**: `npx eslint … | tail` discards the exit code, and v0.19.0 shipped a lint error because of it. Run the gate bare and read its exit status.
- **A second LLM round trip is a real cost to the user.** Structure that needs the model to reason (a plan, an outline) goes in the SAME response, before the payload — not in its own call. Only a failure may cost an extra call.
- **A strip is a chain**: `validatePlan` requires `follows` on every panel after the first. Panels that are individually correct and mutually unrelated are the failure this catches.
- **PLAN, THEN RENDER** (0.18.0): `PLAN_LAWS` lays out beats + who in plain language; `validatePlan` checks the list; `FRAME_LAWS` renders the approved plan into tags. Layout rules belong in the plan prompt, tag rules in the render prompt — never both in one call. A planning failure cannot be fixed downstream, so new checks on strip structure go in `validatePlan`, not in prose.
- **The plan pass must never block an image**: a failed or unparseable plan falls back to the single-call builder.
- **A negative test that passes against a broken build proves nothing about the contract** — assert the OUTPUT of the pipeline (the welded block), not that a helper function exists. This was caught live: the rank-strip guard tested `stripRankInsignia` directly and stayed green when the weld stopped calling it.
- **ONE RULE PER DECISION — never a counter-rule.** 0.16.0 added "padding a frame to two is a failed panel" while 0.12.5's "defaulting to solo is a failed strip" was still live; the builder split the difference into an all-solo strip. When a new rule needs an old one to stay balanced, the old one is wrong and must be REPLACED, not counter-weighted. Before adding to `FRAME_LAWS`, grep it for every existing line touching that decision.
- **Prompt weight is finite**: `FRAME_LAWS` competes with the scene for the builder's attention. Adding a rule has a cost even when the rule is correct — prefer replacing, consolidating, or moving the rule into code.
- **Tags are ASCII**: danbooru tokens have no diacritics. `foldTagDiacritics` runs at composition; never reintroduce a macron/accent spelling into a tag path.
- **A canon character's own danbooru tag outperforms any description** and never drifts between panels — auto-build leads with it. Never invent one for an OC.
- **A law the code cannot enforce is a bug, not a law**: `sanitizeBubbles` promised the speaker's-face rule for three versions without ever receiving `who`. When adding a rule to `FRAME_LAWS`, name the function that enforces it — or do not add it.
- **Canonical prompt constants**: `BUBBLE_RULES`, `GROUNDING_RULE`, and `FRAME_LAWS` (the per-frame law block: who-weld, two-cap, shot grammar, acting density, sentence, clothing/crowd/effect-ownership, WORLD data contract — cited by BOTH the sequence and structured-single-frame modes) are single sources — never restate their content elsewhere. Strip-only rules (chronology, continuity, splitting 3+ beats, camera variation) live in the sequence block. Name escaping is the top-level `escRe` — never inline an escape class into a nested template (that is how the tab-corruption bug shipped).

## Invariants

1. Invented dialogue can never reach an image (verbatim guarantee — negative-tested). Bubble text also never ends mid-sentence: whole ≤110, sentence-boundary cut, or word-cut + ellipsis (negative-tested). Two bubbles render side-by-side in the top band only.
1a000. Gate counts are part of the contract: any edit that lowers the passing count must account for every lost check by name — the 0.10.0 trim silently dropped four suites because an end-anchor overshot and the falling number went unreconciled. When cutting blocks, cut by both start AND end markers of the SAME block, and diff check names before/after.
1a000000000. AUTOMATIC IS DOCTRINE: never suggest the user hand-edit or paste cast sheets — the chain is Canon Grounding wiki cache (chatMetadata.canon_grounding_cache[*].sections.physical, read-only) → canon-verbatim author (source order: wiki > story > canonical knowledge; 'unknown' only for OCs) → per-chat append seeding → one-line-delete refresh. The user runs automatic; respect it.
1a00000000. CINEMA IS CONTRACT: the gold-run grammar (one framing + one angle per panel, never-repeating pairs, lighting/atmosphere, 4-8 acting tags per state) is mandatory — structural correctness without cinematography reads as regression to the user. Active cast is GLOBAL (settings.activeCast); never reintroduce per-chat cast memory — it silently diverged chats onto degraded sheets.
1a0000000. TWO PER FRAME IS PHYSICS: single-prompt anime models cannot hard-bind attributes across 3+ subjects; the who cap is 2, enforced at parse, and multi-principal beats split into more panels. Do not raise this cap on request — the 4-cap experiment produced garment migration (the pink-kimono bug) and was reverted on field evidence.
1a000000. STATE BINDS LIKE IDENTITY: per-character pose/expression/wound tags live in who[].state and are welded by code onto that character's verbatim block — one contiguous run per character. Never let per-character detail live in the shared panel prompt; that soup is what redistributed a dying man's laugh onto his medic. Negative-tested (dropping the weld fails the gate).
1a00000. PROVENANCE FIRST: every generation stamps ENGINE version + active-cast identity into lastDebug/debugPrompts. Any field report is interpreted from those lines, never from output stylometry — three rounds were lost to guessing whether old code or a swapped cast produced paraphrased identity.
1a0000. IDENTITY IS CODE — IN EVERY MODE: named-character appearance is inserted by assembleIdentity from the cast sheet via each panel's `who` list — the builder is contractually and structurally barred from writing named characters' looks. Since 0.13.0 this includes single frames: `structuredSingle` (maxPanels 1 + tags style + cast entries) sends the same who/state/sentence/setting/dress JSON schema, and the who-compliance retry fires ONLY when the schema was actually sent (`schemaSent`) — an unguarded retry burned one contradictory builder call per default-mode image and coin-flipped the identity regime. Never regress identity to builder-written prompt text; every identity bug class this session (substitution, omission, fusion, drift) came from that. Unknown who-names are warned and skipped, never guessed (negative-tested).
1a00. World consistency is DATA + CODE, not instructions: builder emits top-level `dress`/`setting` tag lists once; appendAnchor stamps them (deduped) onto every panel; mineDressTags(cast) is the deterministic backstop. Never regress to per-panel prompt instructions for world consistency — that was the drift bug. Autonomy principle: the user never pastes world facts the extension can derive.
1a0. Panel discipline is contract text in the sequence prompt: 2-character cap, count tags first, full cast tags per character, no role-word clothing, one crowd emotion, speaker faces audience, concrete single-tag actions. These are prompt-level (world knowledge lives in cast tags + Extra builder rules, never hardcoded — model/world-agnostic).
1a. Panel prompts are single frames: layout meta-language (comic/panel/page/grid/multiple views) is contractually banned in the builder prompt and deterministically scrubbed by stripLayoutMeta (negative-tested). SceneSnap media entries carry `scenesnap: true` and their messages get `.scenesnap-media` (append + CHAT_CHANGED + APP_READY) so style.css can lift ST's 40vh cap — keep flag and class in sync.
1b. Sequence mode (Max panels ≥ 2) is a strip contract: the builder prompt floors at 2 panels, panels generate landscape (getSize(landscape) flip), panel seeds are subject-derived from ONE run seed (same who-set → same seed, different who-set → decorrelated; never per-panel random — that re-rolls the characters), the outfit contract repeats full appearance tags verbatim per panel, and stitching cover-fills identical black-framed cells.
2. NOTHING breaks image generation: bubbles and grounding are best-effort layers over the standard single-prompt route — the button never returns empty while that route works. (NAI multi-character mode was removed in 0.10.0: never verified end-to-end, transport dead on the field device across clean browsers; do not resurrect without a full live verification of the final NovelAI hop.)
3. Bubbles OFF means zero bubbles regardless of what the builder returns (gating — negative-tested).
4. Presets and briefs stay model-agnostic; nothing assumes a specific text or image model beyond declared backend prompt styles.
5. Sheetless generation is allowed but never silent (one warning per chat).
6. Every backend HTTP call is same-origin — an ST API route or ST's `/proxy/<url>` CORS proxy. Direct cross-origin `fetch()` is forbidden: the browser blocks it (no CORS headers on NAI et al.) and it fails as an opaque "Failed to fetch" — the exact 0.7.0 multi-char defect. WebSocket backends (Runware) are exempt (no CORS preflight). The harness asserts no direct NovelAI fetch exists. Corollary: a browser-level fetch failure can only mean the ST server is unreachable, and `explainError` (the single reporter path) translates it to say so — keep both sides of that invariant in sync.
7. HTTP failures with a known cause and a one-step fix are classified by pure, negative-tested guards and answered with the fix, never the raw body. Currently: stale page session after an ST restart (403 + 'invalid csrf token' → reload), and browser-level fetch death (→ ST unreachable via explainError). When adding one, capture the real body from a live server first.
8. Third-party URLs are always percent-encoded when embedded in a request path (`/proxy/${encodeURIComponent(url)}`): raw embedded `https://` matches content-blocker circumvention filters and invites path normalization. Express decodes params, so the server sees the same URL either way — verified live.
